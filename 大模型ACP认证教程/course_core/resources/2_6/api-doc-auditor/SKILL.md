# API 文档审核 Skill

此 Skill 用于系统性审核 REST API 文档的质量，确保文档符合专业标准。

## 审核范围

本 Skill 将检查以下三个核心维度：
1. **端点示例完整性** - 每个 API 端点是否包含请求示例和响应示例
2. **错误码说明** - 是否列出常见 HTTP 状态码及其含义和可能原因
3. **参数类型标注** - 请求参数（路径、查询、请求体）是否明确标注数据类型

## 审核流程

### 步骤 1：文档解析
- 识别所有 API 端点（GET/POST/PUT/DELETE 等）
- 提取每个端点的路径、方法、描述
- 识别参数部分（路径参数、查询参数、请求体参数、响应体）

### 步骤 2：逐项检查
对于每个端点，检查：
- ✅ 是否有请求示例（cURL 或其他格式）
- ✅ 是否有成功响应示例（JSON 格式）
- ✅ 是否有错误响应示例（4xx/5xx 状态码）
- ✅ 是否列出并解释常见错误码（如 400, 401, 403, 404, 500）
- ✅ 路径参数是否标注类型（如 `id: integer`, `slug: string`）
- ✅ 查询参数是否标注类型和是否必需（如 `page: integer (required)`, `sort: string (optional)`）
- ✅ 请求体参数是否标注类型、是否必需、是否有示例值

### 步骤 3：生成审核报告

## 报告结构
始终使用这个模板：

# API 文档审核报告

## 概述
- 文档总端点数：[数量]
- 通过端点数：[数量]
- 问题端点数：[数量]
- 整体合规率：[百分比]

## 详细发现

### 端点示例问题
- [端点路径]：缺少请求示例
- [端点路径]：缺少成功响应示例
- [端点路径]：缺少错误响应示例

### 错误码说明问题
- [端点路径]：未列出 401 Unauthorized 错误码说明
- [端点路径]：未列出 404 Not Found 错误码说明
- 全局：错误码说明不一致或缺失

### 参数类型标注问题
- [端点路径]：路径参数 `id` 缺少类型标注
- [端点路径]：查询参数 `limit` 缺少类型标注
- [端点路径]：请求体参数 `email` 缺少是否必需说明

## 建议
- 为所有端点添加标准化的 cURL 请求示例
- 为每个端点添加至少 2 个响应示例（成功 + 常见错误）
- 创建全局错误码参考表
- 使用 OpenAPI 3.0 标准格式化参数定义

## 使用方法
1. 提供 API 文档文件（Markdown、HTML、OpenAPI JSON/YAML 等格式）
2. 本 Skill 将自动解析并执行三重审核
3. 输出结构化审核报告

## 兼容性
- 支持 Markdown 格式 API 文档
- 支持 HTML 格式 API 文档
- 支持 OpenAPI 3.0 JSON/YAML 格式
- 支持 Swagger UI 导出的文档

## 注意事项
- 对于大型文档（>100 个端点），建议分批审核
- 如果文档使用非标准格式，可能需要人工辅助解析
- 本 Skill 不验证 API 实际功能，仅审核文档质量
